# CSV 필드당 200만 자와 초과 항목 제외

- CSV 한 필드의 허용 길이는 2,000,000자다. 정확히 200만 자는 허용하고 초과 시 해당 CSV 레코드 전체를 제외한다.
- 한글의 UTF-8 바이트 수가 아니라 디코딩된 문자 수를 기준으로 한다. 매번 200만 자를 할당하거나 채워 읽지 않는다.
- 일반 레코드는 기존 Python C CSV 파서로 읽는다. 필드 초과 시에만 해당 레코드의 끝을 찾아 건너뛴다.
- 따옴표로 감싼 본문의 줄바꿈과 이스케이프 따옴표를 고려해 다음 CSV 레코드부터 이어 읽는다.
- 사용하지 않는 열을 포함해 모든 필드에 적용한다. 여러 필드가 초과한 한 레코드는 제외 1건이다.
- 미리보기와 전체 건수 확인에서도 초과 항목 때문에 파일 전체가 실패하지 않는다. 모든 데이터가 초과해도 제외 건수를 기록하고 완료한다.
- 초과 항목은 기존 import_failures에 행 번호·사유·작은 오류 메타데이터만 기록한다. 매우 긴 원문을 실패 테이블에 복제하지 않는다. 원본 업로드 CSV는 유지한다.
- 기존 failed_rows에 포함하며, API는 이 중 길이 초과 건수를 unreadable_rows로 별도 반환한다. 재처리 시 체크포인트에 반영된 항목을 중복 집계하지 않는다.
- 처리 완료 메시지와 사이드바에 `필드 길이가 200만 자를 초과하여 읽을 수 없는 CSV 항목 N건은 제외했습니다.`를 표시한다. 0건이면 문구를 표시하지 않는다.
- CSV에서 처리 단위는 레코드(민원 항목)다. 한 파일 안의 초과 항목 때문에 다른 항목을 버리지 않는다.
- 인코딩 오류와 CSV 형식 오류 안내를 구분한다. DB 설정, 임베딩 모델, RAG 및 AI 입력 한도는 변경하지 않았다.

## 검증

- 100,000 / 131,073 / 2,000,000자 허용, 2,000,001자 제외.
- CR/LF/CRLF, 인용 부호·쉼표·여러 줄 본문, 파일 끝 개행 없음, 연속 초과, 사용하지 않는 열 초과.
- 생성한 다양한 CSV 300개 레코드로 초과 항목 제외 후 정상 레코드 내용 유지 확인.
- 별도 테스트 DB에서 정상 민원 저장, 초과 항목 기록, 완료 상태·제외 건수, 재처리 중복 집계 방지, 전체 항목 초과 업로드 확인.
- UI 검사에서 제외 2건 안내·다른 화면에서도 사이드바 안내 유지, 제외 0건 안내 없음 확인.
- 실제 final.csv는 읽기 전용 검사: 45,526건 정상 읽기, 200만 자 초과 0건. 실제 DB에 이 파일을 다시 가져오지 않았다.
- 같은 파일을 각 1회 읽는 단순 비교에서 표준 DictReader 13.892초, 새 파서 13.571초였다. 실행 환경에 따른 변동이 있으므로 고정 성능 보장은 아니다.
