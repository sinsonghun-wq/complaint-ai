# 챗봇과 민원 도구 창

구현·검증일: 2026-10-13.

## 사용 흐름

`AI 추천 답변`에서 대화를 유지하면서 오른쪽 민원 도구 창을 사용한다. 다른 업무 화면으로 이동하지 않는다. 좁은 화면에서는 도구 창을 채팅 아래에 배치한다.

- `내가 민원을 작성하고 싶어`: 새 민원 작성 도구를 연다. 제목·내용을 검토하고 **민원 접수**를 누르면 기존 접수 API로 저장한다.
- `내가 쓴 민원을 확인하고 싶어`: 본인의 목록을 연다. 상세 내용·전달된 공식 답변·이전 민원 정보를 확인한다.
- `42번 민원을 수정하고 싶어`: 본인 민원의 수정 도구를 연다. **수정 저장**을 눌러야 반영한다. 번호가 없으면 목록에서 직접 선택한다.
- `42번 민원을 삭제하고 싶어`: 삭제 확인 도구를 연다. **삭제 확인**을 눌러야 기존 취소 방식으로 처리한다.
- `도구 창 닫아줘`: 도구 창을 숨긴다. 상단 **민원 도구 열기/닫기** 버튼과 창의 닫기 버튼으로도 제어한다.
- 법령·절차 등의 질문: 기존 RAG 추천 답변을 실행한다. 현재 도구에서 작성하거나 선택한 내용의 일부를 함께 전달해 상담할 수 있다.

창을 숨기는 동안 초안과 선택 상태를 유지한다. 같은 민원을 다시 수정 요청하거나 대화의 **도구 다시 열기** 버튼을 사용해도 현재 편집 내용을 유지한다. 새 민원 작성·목록·다른 대상 선택은 해당 도구를 새로 열 수 있다. 새로고침·로그아웃 때 화면 기록은 초기화된다.

옵션의 **새로운 민원 작성하기**는 실제 접수 도구이며, **제목·내용으로 AI 답변 받기**는 접수하지 않는 기존 예상 답변 폼이다. 도구의 AI 답변 버튼도 자체적으로 민원을 저장하지 않는다.

## 구성과 기존 기능 재사용

`POST /api/ai-recommendations/intent`가 설정된 `Qwen3.5-4B`를 Ollama JSON 스키마로 호출한다. `answer / create / list / edit / delete / close_tools`를 구분한다. 최근 대화와 현재 도구 상태는 분류 문맥으로 전달하며, 허용된 출력·입력 크기·명시한 민원 번호를 검사한다.

LLM은 도구를 여는 제안만 한다. 민원 등록·수정·삭제 API를 직접 호출하지 않으며 완료했다고 임의로 말하지 않는다. 의도 구분 모델이 실패하면 오류와 재시도를 제공하고 수동 도구 버튼은 사용할 수 있다.

도구는 기존 `GET/POST /api/complaints`, `GET/PATCH/DELETE /api/complaints/{id}`, 재민원 API를 사용한다. 수정은 접수 대기, 삭제는 접수 대기·접수 됨 상태에서 허용한다. 완료·취소 건과 다른 사용자의 민원은 기존 서버 규칙으로 보호한다. 3초 간격으로 상태를 갱신하고 접근 오류나 상태 변경이 있으면 변경 작업을 차단한다. 목록에는 본인에게 전달된 공식 답변만 표시한다.

문맥은 제목 200자·내용 4,000자 이내다. 모든 긴 원문을 무제한으로 전달하지 않는다. 이전 AI 답변이나 작성 초안을 공식 법령 근거로 간주하지 않으며 기존 답변 모델·지식 색인 한계는 계속 적용된다.

## 검증 결과

- 서버 전체 회귀 테스트 **122건 통과**. 신규 의도 API의 민원인 권한·입력·모델 장애·임의 번호 검사 14건을 포함한다.
- 프런트엔드 전체 **49건 통과**: 기존 챗봇 8, 도구 연결 15, 도구 창 14, 기존 업무 화면 8, 가져오기 진행률 4.
- React 최종 빌드 통과.
- 실제 Qwen3.5-4B 의도 구분: 초기 11건 중 10건 통과. `삭제하지 마`를 창 닫기로 해석한 문제를 보완한 후 최종 프롬프트로 **11건 전체 재시험 통과**. [실측 기록](chat-intent-evaluation-2026-10-13.json)에 초기 실패와 재시험을 함께 보존했다.
- 인증된 API 핸들러·실제 PostgreSQL·실제 의도 모델과 RAG 모델의 통합 시험 **6개 단계 통과**. 도구 요청만으로 접수되지 않음, 명시적 접수·본인 목록, ID를 유지한 수정, 취소 및 목록 제외, 일반 질문의 답변 경로, 소방청 근거를 사용한 RAG 답변을 확인했다. [통합 기록](chat-tools-integration-2026-10-13.json)을 참고한다.

통합 시험의 일반 민원 부서 분류 작업만 명시적인 테스트 대역으로 대체했다. 챗봇 의도 구분·임베딩·재정렬·답변 생성은 실제 모델을 사용했다. 화면 검증은 React DOM 컴포넌트 시험이며 실제 브라우저를 직접 조작한 시각 검증은 수행하지 않았다. 이 소규모 시험은 전체 입력에 대한 의도 정확도나 법률 답변 정확도를 보장하지 않는다. 모델 가중치 학습은 수행하지 않았다.

실측 의도 분류는 최종 시험에서 약 4~17초, 통합 시험의 실제 RAG는 약 53초였다. 모델을 처음 적재하는 경우 더 오래 걸릴 수 있다.

## 재검증

```powershell
cd complaintai-react-fastapi
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
cd frontend
npm test
npm run build
cd ..
.\.venv\Scripts\python.exe scripts/evaluate_chat_intents.py --label rerun
.\.venv\Scripts\python.exe scripts/evaluate_chat_tools.py
```

실제 모델 시험에는 Ollama와 재정렬 서비스가 필요하다. 서버 회귀 테스트와 실제 모델 통합 시험은 순서대로 실행한다. 시험 스크립트는 본인이 만든 임시 계정·민원만 정리한다.
