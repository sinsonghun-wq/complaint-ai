# AI 추천 답변 검증 기록

검증일: 2026-10-07. 초기 모델은 Qwen3-Embedding-0.6B, Qwen3-Reranker-0.6B, Qwen3.5-4B이며 PostgreSQL 16/pgvector 0.8.6을 사용했다. GPU는 GTX 1060 3GB, RAM은 약 16GB다.

## 기능 검증

- 채팅 UI 변경 후 백엔드 전체 회귀 테스트 90건 통과. 기존 민원·권한·수정·취소·CSV 처리와 신규 RAG·후속 질문 기능을 포함한다.
- React 채팅 컴포넌트 테스트 8건, 기존 진행률 테스트 4건 통과. 옵션 메뉴, 채팅 입력·후속 질문, 한국어 조합 중 Enter 전송 방지, 제목·내용 입력, 중복 클릭 방지, 기존 민원 선택, 화면 이동 시 대화 보존, 출처 펼치기·실패 재시도를 확인했다.
- React 배포 빌드 통과. npm audit에서 새 테스트 의존성 설치 후 발견된 간접 의존성을 수정해 0건을 확인했다.
- 추가 DB 마이그레이션을 반복 적용해도 기존 민원과 1536차원 벡터가 보존되는 것을 별도 DB에서 확인했다. 신규 벡터는 1024차원이다.
- 같은 공식 본문·임베딩 프로필을 재import하면 7개 문서를 건너뛰며 중복 문단을 추가하지 않는다.
- API·컴포넌트 단위 테스트의 모델 응답은 test double이다. 아래 실제 모델 평가와 구분한다.
- 브라우저 보안 정책에서 로컬 페이지 접근이 사용자 권한 거부로 차단되어 실제 브라우저 화면 조작은 검증하지 못했다. 다른 브라우저나 우회 경로로 접근하지 않았다.

## 실제 모델 평가와 수정

1. 첫 조건 안내 시험에서 관련 FAQ는 찾았으나 개별 세대 정보 부족을 이유로 일반 조건 설명까지 보류했다. 조건부 안내와 개별 판정을 구분하는 프롬프트를 추가했다.
2. 수정 후 실제 모델 9건의 단순 자동 검사에서는 8건이 통과했다. 원문 대조에서 다음 추가 문제가 드러났다.
   - 주차 신고: FAQ 제목의 질문을 사실로 바꿔 회답에 없는 동영상 인정 주장을 추가했다.
   - 층간소음: 아파트 안내에 비공동주택 문단을 일부 함께 인용했다.
   - 식품 신고: 모르는 업소 정보에 대한 공란 조건을 너무 일반적으로 설명했다.
   - 안심콜: 가입 대상과 연락처 변경의 복합 질문 중 연락처 변경을 누락했다.
3. 질문·회답 분리, 적용 범위 필터, 조건·예외 보존 지시, 질문별 검색·재정렬을 적용했다. 모델 가중치 학습은 수행하지 않았다.

초기 평가의 자동 통과를 법률 답변 정확도로 해석하면 안 된다. 자동 출처·핵심어 검사와 원문 대조 결과를 따로 기록한다.

이전 실제 모델 기록:

- `rag-evaluation-2026-10-07.json`: 초기 조건 안내 실패.
- `rag-evaluation-refined-2026-10-07.json`: 첫 프롬프트 수정 후 9건; 소방 복합 질문 누락과 원문 대조 문제를 포함한다.

## 최종 HTTP 평가

실제 로그인 → HTTP 202 추천 작업 생성 → 단계 조회 → 결과 저장 경로로 9건을 실행했다. 신규 입력 7건, 기존 민원 선택 2건이며 9건 모두 작업 처리가 완료됐다. 프롬프트는 `complaintai-recommendation-ko-v4`다. 예상 상태·출처·핵심어 등 단순 자동 기준은 7건이 통과했다. 이는 법률 답변 정확도 7/9를 의미하지 않는다.

최소 29.07초, 최대 122.57초다. 현재 장비에서 빠른 실시간 답변을 보장할 수 없다. 실행 기록과 답변·근거 snapshot은 [최종 HTTP 평가 JSON](rag-live-api-evaluation-2026-10-07.json)에 보존했다. 원문 대조는 구현 과정에서 수행했으며 별도 법률 전문가 검토는 아직 진행하지 않았다.

안심콜의 누락된 두 번째 질문을 별도로 실제 임베딩·재정렬 모델에 전달했다. 개인정보 변경 시 직접 접속해 정보를 수정하라는 소방청 FAQ가 1위로 검색됐고 재정렬 점수는 0.9046이었다. 이 점수는 답변 정확도 확률이 아니다. [검색 점검 기록](rag-fire-retrieval-review-2026-10-07.json)을 통해 필요한 원문을 찾을 수 있음을 확인했다. 생성 단계의 복합 질문 처리도 개선해야 한다.

평가 스크립트가 만든 임시 계정·민원·추천 기록만 정리했다. 기존 민원 1,438건은 보존됐으며 평가 종료 후 진행 중 추천 작업과 임시 테스트 계정은 0건이었다.

## 학습 판단

현재 corpus는 공식 자료 7개/활성 문단 42개이며 32개 유형 전체를 포괄하지 않는다. 없는 법령·매뉴얼·조례는 추가 학습이 아니라 원문 수집·색인 보강으로 해결해야 한다.

**운영 품질을 목표로 한다면 Qwen3.5-4B 생성 모델 추가 학습이 필요하다고 판단한다.** 검색 구성·원문 분리·적용 범위·프롬프트를 수정한 뒤에도 식품 신고 조건 생략과 복합 질문 답변 누락이 남았다. 필요한 근거는 검색되므로 우선 학습 대상은 생성 모델이다. 이번 소규모 평가만으로 임베딩·재정렬 모델 학습이 필요하다고 결론 내리지는 않는다.

모델 가중치 학습은 아직 수행하지 않았다. 다음 학습 단계에서는 검토된 `민원 제목·내용 + 근거 원문 + 조건·예외와 모든 질문을 보존한 답변` 쌍을 별도로 확보하고 LoRA/QLoRA 추가 학습을 검토한다. 근거 부족 답변, 일반 조건 안내와 개별 판정 구분, 복합 질문, 혼동하기 쉬운 적용 범위도 포함한다. 현재 평가 9건은 학습에 섞지 않고 재평가용으로 보존하며, 추가 독립 사례로 누락·근거 없는 주장·출처 적합성을 평가한다. 학습이 성능 향상을 보장하지 않으므로 같은 기준으로 학습 전후를 비교해야 한다.

현재 PC의 CPU·GPU 일부 실행에 따른 지연은 모델 학습만으로 해결되지 않는다. 운영 목표 시간은 별도 GPU 서버에서 측정해야 한다.

## 채팅 화면 변경 후 실제 대화 검증

채팅 변경 후 프롬프트는 `complaintai-recommendation-ko-v5-chat`이다. 모델 가중치는 학습하지 않았다. 본인 소유의 완료된 추천 작업을 부모로 지정해 후속 질문을 처리하며, 서버에서 이전 사용자 설명·AI 답변을 제한된 맥락으로 읽는다. 검색에는 이전 사용자 설명만 추가하고, 이전 AI 답변을 공식 근거로 취급하지 않도록 지시한다.

실제 로그인·HTTP 요청·세 모델·DB 저장을 사용해 같은 대화에서 아래 2차례 질문을 확인했다.

| 순서 | 질문 | 결과 | 응답 시간 |
|---|---|---|---:|
| 1 | 119안심콜은 고령자만 가입할 수 있나요? | 소방청 FAQ F06의 가입 제한 안내를 근거로 다양한 계층이 가입할 수 있다고 답변 | 64.23초 |
| 2 | 가입한 다음 연락처가 바뀌면 어떻게 해야 하나요? | 이전 작업 ID를 연결하고 F06의 개인정보 수정 FAQ를 근거로 직접 접속하여 정보를 수정하라고 답변 | 47.66초 |

두 요청 모두 완료·공식 출처·부모 대화 연결 검사에 통과했고, 후속 질문의 연락처 수정 안내를 원문과 대조했다. 이 두 사례는 대화 연결의 확인이며 전체 민원 답변 정확도나 앞서 확인한 조건 누락 문제의 해결을 입증하지 않는다. [실제 대화 기록](rag-chat-evaluation-2026-10-07.json)에 답변과 사용한 근거를 보존했다.

초기 실행은 전체 회귀 테스트와 동시에 수행해 테스트용 서버 시작 복구 처리가 실제 시험 작업을 중단했다. 이후 서버 회귀 테스트를 완료한 뒤 실제 모델 시험을 별도로 다시 실행했다. 회귀 테스트에서 막힌 Windows 임시 파일 권한은 승인된 실행 권한으로 재검증했고, 이번 실패 실행이 만든 임시 폴더 10개만 생성 시각·절대 경로를 확인해 정리했다. 기존에 있던 임시 폴더는 정리 대상에 포함하지 않았다.
