# 관리자 파일 민원 분류 복구·검증 — 2026-10-19

## 적용 범위

별도 `complaint AI-main` 작업 폴더. 기존 `complaintAI` 원본 소스, 기존 민원 데이터와 시스템 Tesseract 설치는 덮어쓰지 않았다. GitHub 커밋·푸시는 수행하지 않았다.

임베딩·RAG 모델명, 환경 설정 및 핵심 서비스 코드는 변경하지 않았다. Ollama에 `bge-m3:latest`, `gemma4:e4b`를 설치했으며, 각각 1024차원 벡터 생성과 짧은 답변 `OK`를 실제 확인했다.

## 수정 사항

- CSV: 분리 과정에서 누락된 처리 서비스를 `app/services/imports.py`로 복구. 워커가 웹 앱의 사라진 함수를 import하던 문제와, 실패 안내가 잘못된 DB connection을 사용하던 문제 수정.
- 저장: 500행 트랜잭션·체크포인트, 기본 10행 진행률 갱신, 긴 모델 호출 중에도 10초 heartbeat 기록. 행별 저장 오류는 savepoint로 격리해 실패 행에 기록.
- 분석: 규칙 우선, 저확신 행만 LLM 확인. 파일 분석 LLM은 최대 60초 대기 후 규칙 결과를 유지하고 장애 시 잠시 재호출을 억제. 헤더 매핑은 최대 30초 대기 후 헤더 후보·관리자 확인으로 전환.
- CSV 헤더 앞뒤 공백 정규화. 수동 매핑 경로에서 FastAPI Path와 파일 경로 Path의 혼동 수정.
- XLSX: 모든 데이터 시트·각 행의 독립 처리 유지. PDF/HWP의 1,000번 이상 사례 번호 분리 보완.
- PDF/HWP/XLSX: 추출을 별도 스레드로 실행. 손상된 문서는 일반 HTTP 500 대신 읽기 오류 안내. HWP 파서·변환기의 실행 시간 제한 추가.
- OCR: pdfplumber·PyMuPDF, 프로젝트별 pyhwp 환경, kor/eng 데이터를 준비. 시스템 Tesseract의 DLL 구성이 기존 설치 파일과 달라 실행 오류가 발생했으므로, 동일 설치 파일의 완전한 실행 환경을 프로젝트 `data/tools/tesseract-extracted/`에 분리해 사용. 경로 공백은 인자 리스트 전달로 처리.
- 선택적 파일 벡터 저장: 현재 민원 컬럼 vector(1536)와 bge-m3 출력 1024차원은 불일치한다. 모델·RAG·스키마를 변경하거나 벡터를 패딩/절단하지 않는다. 민원 자체를 정상 저장하고 `analysis_metadata.embedding_warning`에 사유를 기록하며, 같은 묶음에서 저장 불가능한 벡터를 반복 계산하지 않는다.

## 실제 파일 검증

`민원데이터_11개분야_72건` 샘플을 각각 독립 검증했다. 형식이 다른 파일 간 중복 정규화 정확도를 검증한 것은 아니다.

| XLSX | 72 | 72 | 중복 72건 제외 | 72 |
| PDF | 72 | 72 | 중복 72건 제외 | 72 |
| HWP | 72 | 72 | 중복 72건 제외 | 72 |

- 실제 PDF 사례 한 페이지를 텍스트 레이어 없는 스캔 PDF로 만들어 OCR 추출 1건을 확인했다.
- 실제 화면 주소 `http://127.0.0.1:5174`에서도 로그인 및 세 형식 업로드가 HTTP 200으로 각각 72건을 추출했다.
- 일반 사용자 업로드는 HTTP 403으로 차단됨을 확인했다.
- `1-1.csv`: 총 1,297행 완료, 1,296건 저장, 동일 내용 1건 중복 제외, 실패 0건. 규칙 1,279건 / LLM 17건. 약 623.42초 소요(헤더 매핑·모델 대기 포함). 로컬 LLM의 저확신 행 판단이 소요 시간 대부분이며, 파일 읽기 실패나 워커 정지는 아니었다.
- CSV 작업의 저장 건수와 카테고리 건수 합계가 일치했고, 중간 진행률과 heartbeat도 관찰했다.

검증은 별도 임시 DB에서 실행했고, 테스트 종료 후 해당 DB·업로드 파일만 정리했다. 기존 실행 DB의 민원 144건은 보존했다. 원본 파일은 수정하지 않았다.

## 남은 주의 사항

- 파일 민원의 요약·분류·저장은 정상이어도, 현재 민원 벡터 검색은 차원 불일치가 해결된 상태가 아니다. 사용자 요청에 따라 임베딩·RAG 설정은 유지했다. 별도 변경 승인 후 모델·컬럼·검색 쿼리와 재임베딩을 함께 설계해야 한다.
- PDF/HWP 사례 분리는 문서 양식에 의존한다. 임의의 모든 문서에서 민원 경계를 정확히 찾는다는 보장은 없다. 이미지 전용 HWP는 변환기 준비도 필요하다.
- Python 가상환경·모델·OCR 실행 파일·언어 데이터는 Git 관리 대상이 아니다. 다른 컴퓨터는 README의 설치 절차를 별도로 수행해야 한다.
