# RAG용 데이터 삽입

관리자의 ‘새 민원’ 화면에서 기존 파일 가져오기 아래에 RAG 자료 입력 영역을 추가했다.
CSV 원본은 기존 업로드 폴더에 보관하고, 각 레코드는 기존 `public.department_documents`에 저장한다.
민원 `complaints`에는 저장하지 않는다.

- CSV 전용이며 PDF/HWP/XLSX 등은 파일 형식 안내와 함께 거부한다.
- `제목,본문`, `title,content`, 법령명/조문내용 등 본문 열 이름을 자동으로 인식한다.
  사례는 `제목,질문,답변`도 지원한다. 따로 CSV 열 매핑 화면을 요구하지 않는다.
- 본문은 공백·줄바꿈·인용 부호까지 CSV에서 읽은 그대로 저장한다.
  질문/답변 사례는 ‘질문: …\n답변: …’ 형태로 함께 저장한다.
- CSV에 벡터가 있더라도 현재 doc-main의 임베딩 함수와 모델로 본문의 벡터를 새로 생성한다.
  실제 환경은 `bge-m3:latest`, 1024차원이며 벡터가 없거나 차원이 다르면 저장하지 않고 오류를 안내한다.
- 같은 본문은 제목·파일명·부서와 관계없이 중복으로 제외한다. 공백이 다른 본문은 별개다.
  인덱스는 `md5(content)`로 후보를 찾고 원문 전체를 비교한다. 동시에 저장해도 작업 잠금으로 중복을 막는다.
- 새로운 `rag_import_jobs`와 `rag_import_failures`가 상태·저장 건수·중복·제외 항목을 기록한다.
  기존 테이블/데이터를 삭제하거나 계정의 담당 부서를 변경하지 않는다.
- 자료 부서는 로그인 계정의 부서를 기본값으로 사용한다. 미지정이면 기타가 기본값이며 직접 선택할 수 있다.
- 별도 `python -m app.rag_worker`를 사용한다. 기존 민원 CSV 워커와 동시에 동작할 수 있다.
  화면 사이드바는 민원 파일 처리 위, RAG 파일 처리 아래 순서다.
- 기본 100개 레코드마다 본문·임베딩·진행 상태를 한 트랜잭션으로 확정한다. 마지막 잔여분도 저장한다.
  진행률은 확정된 건수만 반영한다. 중복/제외가 있으면 처리 건수와 실제 저장 건수를 나눠 표시한다.
- 취소 API는 저장 트랜잭션과 같은 작업 행을 잠근다. 취소 확정 후 추가 저장을 막고 미저장 배치는 버린다.
  이미 확정된 자료와 원본 업로드는 유지하며 ‘해당 작업이 취소되었습니다.’를 표시한다.
  임베딩 요청 중에도 취소를 확인하고 대기 작업을 종료한다.
- 페이지 이동·새로고침 시 본인의 최근 작업을 불러온다. 다른 관리자의 작업을 취소할 수 없다.
- 기존 `agent.aiFAQ` 검색과 추천 답변 프롬프트, DB 접속 설정, 임베딩 모델 설정은 유지했다.
  `aiFAQ`가 `department_documents`를 직접 검색하므로 새 자료가 기존 검색에 반영된다.

## 검증

별도 PostgreSQL 테스트 DB에서 100 → 200 → 205건의 실제 저장과 진행 상태를 확인했다.
원문·1024차원 벡터, 반복/다른 부서/동시 업로드 중복, 초과 행 제외, 권한, 임베딩 실패,
100건 이후 및 임베딩 도중 취소, 취소 후 미저장 배치 차단을 검증했다.
UI는 CSV 형식 거부, 두 진행률의 순서, 실제 건수 표시, 다른 화면에서 취소,
업로드 응답 대기 중 취소, 지연 응답 무시, 최근 작업 복원을 검사했다.

격리된 브라우저 환경에서 실제 bge-m3 모델로 200건을 저장하고 취소했다.
DB 건수는 200건으로 유지됐고 모두 1024차원이며 빈 벡터는 없었다.
테스트 자료는 사용자의 실제 RAG 자료 테이블에 넣지 않았다.

실제 8000번 백엔드에도 반영했다. DB 상태 확인과 관리자용 최근 RAG 작업 API는 모두
HTTP 200이며, 별도 RAG 워커가 준비된 것을 확인했다. 5173번 화면에서도 입력 영역을 확인했다.
관리자 UI 테스트 77개와 진행률 테스트 4개가 모두 통과했다.
브라우저 검증용 임시 DB는 제거했고 실제 `department_documents`의 자료 수는 0건을 유지했다.
