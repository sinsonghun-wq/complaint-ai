# 긴 원문의 답변 근거와 대기 시간 설정

## 적용 범위

- 긴 원문에서 답변에 제공하는 근거 본문은 질문당 합계 최대 **5,000자**다. 선택된 여러 긴 원문과 근거 미완료 안내가 이 예산을 함께 사용한다.
- 원문 ID, 자료명, 시행일, 개정 정보, 조항 제목과 구분 문자도 근거 본문 길이에 포함한다. 프롬프트·대화 이력·도구 응답의 JSON 구조는 별도다.
- `department_documents` 원문과 `department_documents_chunks`의 내용·벡터·분할 방식은 변경하지 않는다. 전체 원문과 모든 조각이 계속 검색 후보다.
- 기존 짧은 원문 경로는 그대로 유지한다. 문서당 앞 5,000자를 제공하며, 짧은 원문 여러 건과 긴 원문이 함께 선택된 경우 전체 도구 응답이 5,000자를 넘을 수 있다. 새 5,000자 합계는 긴 원문 근거에 적용한다.

## 근거 구성

1. 기존 벡터 검색과 원문 선정은 유지한다.
2. 검색된 조각에 해당하는 조항을 원문 ID와 위치로 확인한다.
3. 각 조항을 확장 대기열에 넣기 전에, 조항 전체와 출처 표기를 더해도 남은 문자 예산 안에 들어가는지 검사한다.
4. 인접 예외·역방향 예외·내부 참조·명시적 외부 법령을 기존 방식으로 확인하되, 예산을 초과하면 그 이후의 연결 조회는 진행하지 않는다. 이미 포함된 같은 조항의 중복 확장에는 문자를 다시 차감하지 않는다.
5. 필수 근거가 한도를 넘으면 원칙 조항의 앞부분만 잘라 제공하지 않는다. 해당 원문의 본문을 `근거 확인 미완료`와 한도 초과 사유로 대체한다. 이 안내도 5,000자 예산에 포함한다. 뒤의 후보를 위한 안내 공간을 남겨 둔다.
6. 기존 답변 모델의 토큰 예산 검사도 추가 안전장치로 유지한다. 원문이나 조각을 다시 임베딩할 필요는 없다.

이 표시는 모델에 확인 미완료 사실과 단정 금지를 전달하는 방식이다. 모델의 최종 문장에 대한 별도 강제 검증 기능을 추가한 것은 아니다. 문자 예산 적용으로 모든 질문의 정확도·응답 시간이 기존과 같아진다고 보장하지 않는다.

## 시간 설정

| 구분 | 이전 | 변경 후 |
|---|---:|---:|
| RAG 검색 전체 | 30초 | **600초(10분)** |
| 채팅 요청 전체, 대기열 포함 | 180초 | **1,200초(20분)** |
| 브라우저 최종 대기 | 190초 | **1,210초(20분 10초)** |

브라우저는 서버가 시간 초과 응답을 돌려줄 수 있도록 10초 여유를 둔다. 취소 버튼과 연결 종료 시 작업 취소는 유지한다. `CHAT_REQUEST_TIMEOUT_SECONDS` 환경 변수가 있다면 서버 기본값보다 우선하지만, 현재 로컬 환경에는 별도 지정이 없다. DB 개별 연결·SQL 및 AI 통신의 기존 제한은 유지한다.

## 검증 항목

- 정확히 5,000자까지의 조항은 전체 제공하고, 초과하면 근거 미완료로 처리한다. 한글·이모지·원문 내용은 보존한다.
- 큰 시작 조항은 추가 외부 참조 SQL을 실행하기 전에 중단한다. 필수 외부 예외가 한도를 넘으면 원칙만 제공하지 않고 이후 법령 조회도 중단한다.
- 공유 참조의 중복 예산 차감 방지, 여러 긴 원문의 합계와 안내 분량 제한, 짧은 원문 혼합 검색의 기존 동작을 확인한다.
- 시간 초과·취소 후 워커 복구와 브라우저가 기존 190초에 끊지 않는지 확인한다.
- 원문 전체 대비 정확도 및 응답 시간 3배 미만 목표는 별도의 비교 시험이 필요하다.

### 이번 변경의 실행 결과

- 분량·참조 그래프·취소·시간 초과 17개와 긴 원문 가져오기·기존 RAG 가져오기·민원 검색 범위 33개, 합계 백엔드 50개 통과.
- 현재 화면 계약을 검증하는 `npm run test:admin`의 84개 및 진행률 4개 통과. 프런트엔드 빌드 성공.
- 전체 `npm test`에는 이전의 다른 채팅 API·응답 형식을 기대하는 두 파일의 28개 실패와 4개 미처리 오류가 남아 있다. 이번 변경 직전 `AIRecommendations.jsx`를 별도 Vite 로더로 적용한 비교 실행에서도 같은 28개 실패와 4개 오류를 재현했다. 이 작업에서 이전 채팅 흐름으로 제품 코드를 변경하거나 해당 테스트를 삭제하지 않았다.
- 실제 기존 임베딩 서버와 운영 DB를 읽는 검색 확인: 긴 원문 근거 합계 2,833자, 그중 2건 확인 완료·1건 기존 참조 미확인 안내, RAG 약 0.493초. 이는 검색 확인이며 최종 답변 생성까지의 성능 비교는 아니다.
- 운영 원문 99,235건, 조각 160,014건, 완료 원문 2,098건 및 `.env` 해시가 변경 전과 같음을 확인했다. 원문 삽입·삭제·재임베딩을 수행하지 않았다.
