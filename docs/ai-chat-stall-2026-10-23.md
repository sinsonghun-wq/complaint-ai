# 문의 모드의 장시간 대기 수정

이 문서는 최초 수정 당시의 기록이다. 이후 사용자 요청으로 긴 원문 근거를 질문당 합계 5,000자, RAG 검색을 600초, 채팅 전체를 1,200초, 브라우저 대기를 1,210초로 조정했다. 현재 설정과 검증 범위는 [긴 원문 근거와 대기 시간 설정](rag-evidence-budget-2026-10-23.md)을 참고한다.

## 원인

2026-10-23 문의 모드 요청이 처리 시작 후 한 시간 이상 반환되지 않았다. 당시 AI 서버는 생성 중이 아니었고 PostgreSQL에는 외부 참조 법령 조회가 반복되고 있었다.

- 참조 확장이 경로마다 같은 자료를 다시 읽었다. 보조 정의·적용범위에 나열된 관계없는 법령까지 재귀적으로 확장해 조회량이 커졌다.
- 서로 다른 인용부호를 짝지어 본문 일부를 법령명으로 인식하는 경우가 있었다.
- 법령명 조회용 인덱스가 없었고, 조각 검색의 상태 조인 조건 때문에 PostgreSQL이 HNSW 대신 모든 조각을 정렬하는 실행계획을 골랐다.
- 채팅의 단일 워커가 전체 요청의 종료 시한 없이 기다렸다. 프런트엔드에도 해당 요청의 시간 제한과 취소 기능이 없어 뒤의 요청까지 대기할 수 있었다.

## 변경

- 원문별 조항을 그래프로 조회한다. 같은 조항의 중복 확장을 막고 원문·법령 버전 조회를 요청 안에서 재사용한다.
- 직접 참조 조항, 인접·역방향 예외는 계속 확인한다. 보조 정의·적용범위는 조문 전체를 제공하되, 그 안의 관계없는 참조까지 자동으로 연쇄 확장하지 않는다. 직접 참조된 조항으로 승격되면 필요한 참조를 확인한다.
- 최대 16개 원문·32개 법령 조회·96개 조항 및 전체 RAG 30초로 한 요청의 확장을 제한한다. 필요한 근거를 모두 확인하지 못하면 부분 규정으로 단정하지 않도록 근거 미확인을 전달한다.
- 법령명 인용부호의 짝을 구분한다. 기존 저장 원문에서 검색할 때 연결 메타데이터를 다시 해석하므로 기존 원문이나 조각 벡터를 다시 저장할 필요가 없다.
- `20261023_rag_reference_lookup.sql`로 `md5(title)` 조회 인덱스를 추가한다. 현재 DB의 통계도 `ANALYZE`로 갱신했다. 원문·벡터를 변경하는 작업은 아니다.
- 검색 가능한 완료 원문과 개정본을 먼저 정한 뒤, 조각의 벡터 검색을 조인보다 먼저 수행한다. 상위 후보를 고른 뒤 게시 상태·삭제 여부·모델을 다시 확인한다. 미완성 또는 다른 개정본을 검색 대상으로 섞지 않는다.
- RAG SQL은 연결 3초·개별 문장 5초 제한을 사용한다. 요청 취소 시 진행 중인 참조 탐색도 종료되도록 취소 신호를 전달한다.
- 채팅 전체는 기본 180초 제한이다. `CHAT_REQUEST_TIMEOUT_SECONDS`로 조정할 수 있다. 만료된 대기 요청은 실행하지 않으며, 오류·취소가 다음 요청의 처리를 막지 않는다.
- 브라우저는 190초 안에 응답하지 않으면 로딩을 끝내고 재시도를 안내한다. 사용자가 **답변 요청 취소**를 눌러 중단할 수 있다. 연결 종료 시 백엔드의 해당 요청도 취소한다.
- `GET /health/chat`에서 워커 상태, 큐 길이, 처리 단계와 경과 시간을 볼 수 있다. 질문 내용이나 사용자 식별자는 반환하지 않는다.

## 검증

- 백엔드 전체 131개 테스트 통과. 마지막 벡터 조회 쿼리 수정 뒤 관련 23개 테스트 추가 통과.
- 관리자 화면 83개와 진행률 4개 테스트 통과, 프런트엔드 빌드 성공.
- 취소·시간 초과 후 다음 요청의 정상 처리, 만료된 요청의 실행 방지, 공유 참조의 중복 조회 방지, 필수 참조 누락 시 근거 미확인 처리를 검증했다.
- 실제 DB의 이의신청 제35조 근거 조립은 약 0.03초, 벡터 후보 조회는 약 0.42초로 측정했다.
- 실제 BGE-M3와 기존 답변 생성 모델을 연결한 `/api/chat` 검증에서 이의신청 질문은 HTTP 200으로 반환됐다. RAG 약 1.37초, 전체 약 134.18초였다. 답변에 60일·10일·연장 10일과 이의신청 여부와 관계없는 심판·소송 가능 여부가 포함됐다. 이 시간은 해당 질문과 당시 자원 상태에서의 측정값이다.
- 실제 응답 시험은 별도 메모리의 진단 워커로 실행했다. 민원을 접수하거나 RAG 원문·조각을 삽입하지 않았다.

실행 중이던 오래된 요청은 백엔드 재시작으로 종료했다. 화면을 새로고침한 뒤 문의를 다시 전송하면 수정된 처리 경로를 사용한다. DB 접속 설정, 임베딩·답변 생성 모델, 원문과 저장된 조각 임베딩은 유지한다.
